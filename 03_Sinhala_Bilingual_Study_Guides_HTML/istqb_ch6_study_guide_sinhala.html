Chapter 06: Test Tools (පරීක්ෂණ මෙවලම්)

ISTQB CTFL v4.0.1 Syllabus • Bilingual Master Study Guide (English Official Terms with Comprehensive Sinhala Explanations)

1. Core Syllabus Concepts & In-Depth Notes (මූලික විෂය කරුණු)

6.1 Tool Support for Testing (පරීක්ෂාව සඳහා මෙවලම් සහාය) FL-6.1.1 (K2)

නිල අර්ථ දැක්වීම (Core Definition): A Test Tool in the context of software testing is any software product or utility that supports and facilitates one or more test activities throughout the software development lifecycle.
(මෘදුකාංග පරීක්ෂාවේදී "පරීක්ෂණ මෙවලමක්" යනු මෘදුකාංග සංවර්ධන ජීවන චක්‍රය (SDLC) පුරා සිදුවන පරීක්ෂණ ක්‍රියාකාරකම් එකක් හෝ කිහිපයක් පහසු කිරීමට හා කාර්යක්ෂම කිරීමට සහාය වන ඕනෑම මෘදුකාංගයක් හෝ උපයෝගීතාවයකි.)

Primary Tool Categories Supporting Core Testing Activities (ප්‍රධාන මෙවලම් කාණ්ඩ):

1. Test Management Tools (පරීක්ෂණ කළමනාකරණ මෙවලම්) Management Support
ප්‍රධාන කාර්යභාරය (Primary Function): SDLC ක්‍රියාවලිය, අවශ්‍යතා (Requirements), පරීක්ෂණ අවස්ථා (Test Cases), දෝෂ (Defects) සහ Configuration Baselines කළමනාකරණය කිරීම හරහා සමස්ත පරීක්ෂණ ක්‍රියාවලියේ කාර්යක්ෂමතාව ඉහළ නැංවීම.
• Test cases, suites සහ test execution runs ගබඩා කර තබන මධ්‍යම ගබඩාවක් (Central repository) සපයයි.
• අවශ්‍යතා, අවදානම්, පරීක්ෂණ සහ දෝෂ අතර ද්වි-දිශා සොයාගැනීමේ හැකියාව (Bidirectional Traceability) පවත්වා ගනී.
• ප්‍රමාණාත්මක ප්‍රගති මිනුම් (Metrics), Burndown charts සහ තත්ත්ව වාර්තා (Progress/Completion Reports) සකස් කරයි.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: Jira, Azure DevOps (Test Plans), HP ALM/Quality Center, TestRail, Zephyr, Xray.
2. Static Testing Tools (ස්ථිතික පරීක්ෂණ මෙවලම්) Static Analysis Support
ප්‍රධාන කාර්යභාරය (Primary Function): මෘදුකාංග කේතය ක්‍රියාත්මක නොකර (without executing code) සමාලෝචන (Reviews) සහ ස්ථිතික විශ්ලේෂණ (Static Analysis) සිදුකිරීමට සහාය වීම.
• Review Support Tools: සමාලෝචන ක්‍රියාවලිය කළමනාකරණය, ලියකියවිලි බෙදාහැරීම, අදහස් (comments) එක්රැස් කිරීම සහ අඩුපාඩු නිරීක්ෂණය.
• Static Analysis Tools (Linters/Analyzers): කේත සම්මතයන් (Coding standards) බලාත්මක කිරීම, කේතයේ විෂමතා සෙවීම, ආරක්ෂක දුර්වලතා (SAST) හඳුනාගැනීම, සහ Cyclomatic Complexity ගණනය කිරීම.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: SonarQube, Checkmarx, Fortify, ESLint, Pylint, Coverity, Crucible.
3. Test Design and Implementation Tools (සැලසුම් සහ ක්‍රියාත්මක කිරීමේ මෙවලම්) Testware Generation
ප්‍රධාන කාර්යභාරය (Primary Function): Test cases, Test data, සහ ක්‍රියාත්මක කළ හැකි Test procedures ස්වයංක්‍රීයව හෝ අර්ධ-ස්වයංක්‍රීයව උත්පාදනය කිරීමට පහසුකම් සැලසීම.
• Requirements, Models (Model-Based Testing), State machines මත පදනම්ව inputs සහ expected outputs ස්වයංක්‍රීයව සෑදීම.
• සංයෝජන පරීක්ෂණ (Combinatorial testing) සඳහා අවශ්‍ය කෘත්‍රිම (Synthetic) හෝ Sanitized පරීක්ෂණ දත්ත ජනනය කිරීම.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: Model-based testing tools (GraphWalker, Conformiq), Test data generators (Mockaroo), Combinatorial tools (ACTS, PICT).
4. Test Execution and Coverage Tools (ධාවන සහ ආවරණ මෙවලම්) Execution & Measurement
ප්‍රධාන කාර්යභාරය (Primary Function): පරීක්ෂණ ස්වයංක්‍රීයව ධාවනය කිරීම සහ කේත ආවරණය (Code Coverage) වෛෂයිකව මැන බැලීම.
• Test Execution Tools: ස්වයංක්‍රීය scripts ධාවනය කර, සත්‍ය ප්‍රතිඵලය අපේක්ෂිත ප්‍රතිඵලය සමඟ සසඳා Pass/Fail තීරණය වාර්තා කිරීම (Test harnesses, Test runners).
• Coverage Tools: පරීක්ෂණ මඟින් ආවරණය වූ කේතයේ ප්‍රතිශතය (Statement coverage, Branch coverage) සංඛ්‍යාත්මකව මැන බැලීම.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: Selenium, Playwright, Cypress, Appium, JUnit, NUnit, JaCoCo, Istanbul.

1.1 Secondary & Infrastructure Tool Categories

5. Non-Functional Testing Tools (කාර්යබද්ධ-නොවන පරීක්ෂණ මෙවලම්) Quality Characteristics
ප්‍රධාන කාර්යභාරය (Primary Function): මිනිසුන්ට අතින් (Manually) සිදුකිරීමට නොහැකි හෝ අතිශය අපහසු මෘදුකාංග ගුණාංග පරීක්ෂා කිරීමට ඉඩ සලසයි.
• Performance & Load Tools: එකවර පරිශීලකයින් දහස් ගණනක් (Concurrent users) පද්ධතියට පිවිසෙන ආකාරය අනුකරණය කරමින් ප්‍රතිචාර කාලය (Response time) සහ පද්ධතියේ ධාරිතාව මැනීම.
• Security Testing Tools (DAST/Penetration): ධාවනය වන යෙදුමක පවතින ආරක්ෂක සිදුරු (SQL injection, XSS) ස්කෑන් කර සොයාගැනීම.
• Reliability & Chaos Tools: ජාල ප්‍රමාදයන් (Latency), Server බිඳවැටීම්, සහ Memory leaks පරීක්ෂා කිරීම.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: Apache JMeter, k6, LoadRunner, Gatling, OWASP ZAP, Burp Suite.
6. DevOps Tools (CI/CD සහ Deployment මෙවලම්) Pipeline & CI/CD
ප්‍රධාන කාර්යභාරය (Primary Function): DevOps continuous delivery pipeline, ස්වයංක්‍රීය Build ක්‍රියාවලිය, සහ Continuous Integration / Continuous Deployment (CI/CD) සඳහා සහාය වීම.
• සංවර්ධකයින් කේතය commit කළ වහාම ස්වයංක්‍රීය Smoke, Unit සහ Regression tests ක්‍රියාත්මක කරවීම.
• පරීක්ෂණ අසමත් වුවහොත් හෝ කේත ආවරණය අඩු වුවහොත් Build එක ඉදිරියට යාම වැළැක්වීමේ Quality Gates සැපයීම.
කර්මාන්තයේ ප්‍රමුඛ උදාහරණ: Jenkins, GitLab CI, GitHub Actions, CircleCI, ArgoCD.
7. Collaboration Tools Communication
කාර්යය: කණ්ඩායමේ සාමාජිකයන් අතර සන්නිවේදනය සහ සහයෝගීතාවය පහසු කිරීම.
• ක්ෂණික පණිවිඩ හුවමාරුව, වීඩියෝ සාකච්ඡා, කණ්ඩායම් පුවරු (Kanban) සහ ලේඛන හවුලේ සැකසීම.
උදාහරණ: Slack, Microsoft Teams, Confluence, Miro, Trello.
8. Virtualization & Containers Infrastructure
කාර්යය: පරීක්ෂණ පරිසරයන් (Test environments) පරිමාණය කිරීම, හුදකලා කිරීම සහ ප්‍රමිතිගත කිරීම.
• අවශ්‍ය විටක ක්ෂණිකව එකම ආකාරයේ පරිසරයන් නිර්මාණය කරගැනීම.
උදාහරණ: Docker, Kubernetes, VMware, VirtualBox.
9. The Spreadsheet Principle ("පැතුරුම්පත් මූලධර්මය"):

විෂය නිර්දේශය පැහැදිලිවම අවධාරණය කරන්නේ: පරීක්ෂණ කටයුත්තක් සඳහා සහාය වන ඕනෑම මෘදුකාංගයක් පරීක්ෂණ මෙවලමක් ලෙස සැලකේ.
• ප්‍රධාන විභාග උදාහරණය: Test cases සටහන් කිරීමට, පරීක්ෂණ පියවර ලිවීමට හෝ Pass/Fail ප්‍රතිඵල සටහන් කිරීමට භාවිත කරන Spreadsheet එකක් (Microsoft Excel, Google Sheets) පරීක්ෂණ සන්දර්භය තුළදී නිල වශයෙන් පරීක්ෂණ මෙවලමක් (Test Tool) ලෙස වර්ගීකරණය කෙරේ!
• එසේම SQL clients, Text editors, API inspection proxies (Postman), සහ Diff tools පරීක්ෂාවේදී Test Tools වේ.

Master Traceability: Test Activities (Chapter 1) to Tool Categories

පරීක්ෂණ ක්‍රියාකාරකම (Section 1.4.1) සහාය වන ප්‍රධාන මෙවලම් කාණ්ඩය ටෙස්ටර්ට ලැබෙන ප්‍රධාන ප්‍රතිලාභය
Test Planning & Control Test Management Tools, Spreadsheets කාලසටහන්, සම්පත් කළමනාකරණය, පරිශ්‍රම ලුහුබැඳීම සහ මිනුම්.
Test Analysis & Design Test Design Tools, Static Analysis Tools අවශ්‍යතාවල දෝෂ සෙවීම, State models හැදීම, Test cases ජනනය.
Test Implementation Test Implementation Tools, Data Generators පරීක්ෂණ දත්ත සැකසීම, Harnesses සැකසීම, Scripts ලිවීම.
Test Execution Test Execution Tools, Non-Functional Tools Regression tests ස්වයංක්‍රීයව run කිරීම, බහු-පරිශීලක load අනුකරණය.
Test Completion Reporting Tools, Collaboration Tools මිනුම් එක්රැස් කිරීම, Completion reports සෑදීම, Testware ලේඛනාගාරගත කිරීම.

1.2 Benefits and Risks of Test Automation FL-6.2.1 (K1)

මූලික ස්වයංක්‍රීයකරණ නියමය (The Fundamental Automation Axiom):
"Simply acquiring a tool does not guarantee success. Each new tool will require effort to achieve real and lasting benefits (e.g., for tool introduction, maintenance, and training). There are also some risks, which need analysis and mitigation."
(මිල අධික මෙවලමක් මිලදී ගත් පමණින් සාර්ථකත්වය ළඟා කරගත නොහැක. සැබෑ හා දිගුකාලීන ප්‍රතිලාභ ලැබීමට නම් මෙවලම හඳුන්වාදීම, අඛණ්ඩ නඩත්තුව සහ කාර්ය මණ්ඩල පුහුණුව සඳහා ශ්‍රමය වැය කළ යුතුය.)

The 6 Potential Benefits of Test Automation (ස්වයංක්‍රීයකරණයේ නිල ප්‍රතිලාභ 6)

නිසි ලෙස සැලසුම් කර නඩත්තු කරන ස්වයංක්‍රීයකරණයකින් ලැබෙන ප්‍රධාන වාසි 6:

1. Time Saved by Reducing Repetitive Manual Work (පුනරාවර්තී වැඩ අවම වීමෙන් කාලය ඉතිරිවීම)

මිනිසුන් අතින් සිදුකිරීමට වැඩි කාලයක් ගතවන ඒකාකාරී, පුනරාවර්තී කාර්යයන් ස්වයංක්‍රීය මෙවලම් මඟින් බාරගනී.
• එක් එක් build එක සහ sprint එකක් පාසා Regression test suites නැවත නැවත ක්‍රියාත්මක කිරීම.
• විශාල දත්ත කට්ටල (Data permutations) නැවත නැවත පද්ධතියට ඇතුළත් කිරීම.
• දත්ත දසදහස් ගණනක අපේක්ෂිත ප්‍රතිඵල සත්‍ය ප්‍රතිඵල සමඟ ස්වයංක්‍රීයව සංසන්දනය කිරීම.

2. Prevention of Simple Human Errors Through Consistency & Repeatability (මානව දෝෂ වැළැක්වීම)

පුනරාවර්තී කාර්යයන් කිරීමේදී මිනිසුන්ට වෙහෙස (Fatigue) හා නොසැලකිලිමත්කම නිසා වැරදීම් සිදුවීම සාමාන්‍ය දෙයකි.
• පරීක්ෂණ සෑම විටම එකම නිරවද්‍යතාවයෙන්, එකම අනුපිළිවෙලින් සහ නියමිත වේලාවට ධාවනය වේ.
• අතින් ටයිප් කිරීමේදී සිදුවන වැරදි (Typing mistakes) තොරව පරීක්ෂණ දත්ත නිවැරදිව භාවිත වේ.

3. More Objective Assessment and Complex Measurement (වෛෂයික ඇගයීම සහ සංකීර්ණ මිනුම්)

මිනිස් ඇසට හෝ මනසට අතින් ගණනය කළ නොහැකි සංකීර්ණ තාක්ෂණික මිනුම් වෛෂයිකව ලබාදෙයි.
• අපක්ෂපාතී කේත ආවරණ මිනුම් (e.g. 85% statement coverage, 70% branch coverage) ලබාදීම.
• මිනිසුන්ට අතින් මැනිය නොහැකි මයික්‍රෝතත්පර ප්‍රමාදයන් (Microsecond latency), Memory leak අනුපාත, සහ Cyclomatic complexity ලකුණු නිවැරදිව මැනීම.

4. Easier Access to Information to Support Test Management & Reporting (තොරතුරු ලබාගැනීමේ පහසුව)

පරීක්ෂණ දත්ත ස්වයංක්‍රීයව එක්රැස් කර සජීවී වාර්තා බවට පත්කරයි.
• සජීවී Pass/Fail සංඛ්‍යාලේඛන, ප්‍රවණතා ප්‍රස්තාර (Trend charts) සහිත Dashboards සැපයීම.
• පරීක්ෂණ ප්‍රගතිය, අසමත් වීමේ අනුපාත (Failure rates), සහ ධාවන කාලය පිළිබඳ සම්පිණ්ඩිත දත්ත ලබාදීම.

5. Reduced Execution Time & Faster Feedback

ස්වයංක්‍රීය පරීක්ෂණ අතිශය වේගයෙන් ධාවනය වේ. සංවර්ධකයින්ට කේතයේ වැරදි පිළිබඳ ක්ෂණික ප්‍රතිපෝෂණ (Instant feedback) ලැබෙන අතර Time-to-market වේගවත් කරයි.

6. More Time for Deeper, Effective Testing

ඒකාකාරී Regression පරීක්ෂණවලින් ටෙස්ටර්වරුන් නිදහස් වන බැවින්, වඩාත් ගැඹුරු හා නිර්මාණශීලී Exploratory testing සිදුකිරීමට මිනිස් බුද්ධිය යෙදවීමට කාලය ලැබේ.

1.3 Risks of Test Automation & Strategic Mitigations (අවදානම් 8 සහ පිළියම්)

ස්වයංක්‍රීයකරණය අසාර්ථක වන්නේ මෙවලමේ වරදින් නොව, කළමනාකරණ හා ආයතනික වැරදි නිසාවෙනි. විෂය නිර්දේශයේ දක්වා ඇති ප්‍රධාන අවදානම් 8:

1. Unrealistic Expectations About Tool Benefits

අවදානම: මෙවලම මඟින් "සියලු ගැටලු විසඳනු ඇත" හෝ 100% ක් ස්වයංක්‍රීය කරනු ඇතැයි කළමනාකාරිත්වය අතිශයෝක්තියෙන් සිතීම.
පිළියම: යථාර්ථවාදී ඉලක්ක තැබීම; ස්වයංක්‍රීයකරණයද මෘදුකාංග සංවර්ධනයක් බව වටහා ගැනීම.

2. Inaccurate Estimations of Time, Cost & Effort

අවදානම: මෙවලම හඳුන්වාදීමට, කාර්ය මණ්ඩලය පුහුණු කිරීමට, සහ නිරන්තරයෙන් scripts නඩත්තු කිරීමට (Maintenance) වැයවන විශාල ශ්‍රමය අවතක්සේරු කිරීම.
පිළියම: අඛණ්ඩ නඩත්තුව සඳහා අයවැය සහ කාලය වෙන්කිරීම (මුල් ශ්‍රමයෙන් 30-50%).

3. Automating When Manual Testing Is More Appropriate

අවදානම: ඉක්මනින් වෙනස්වන UI prototypes, එක්වරක් පමණක් කරන exploratory පරීක්ෂණ හෝ usability පරීක්ෂණ ස්වයංක්‍රීය කිරීමට උත්සාහ කිරීම.
පිළියම: ස්ථාවර regression පරීක්ෂණ පමණක් ස්වයංක්‍රීය කිරීම; usability මිනිසුන් ලවා සිදුකිරීම.

4. Relying on a Tool Too Much (Ignoring Critical Thinking)

අවදානම: Automated tests සියල්ල pass වූ පමණින් කිසිදු දෝෂයක් නැතැයි සිතා මිනිස් බුද්ධිය හා විවේචනාත්මක චින්තනය අත්හැරීම.
පිළියම: Automation යනු regression දැලක් පමණක් බවත්, මිනිස් බුද්ධියට විකල්පයක් නොවන බවත් තේරුම් ගැනීම.

5. Tool Vendor Dependency

අවදානම: වාණිජ මෙවලම් විකුණන සමාගම බංකොලොත් වීම, මෙවලම අත්හැර දැමීම, හෝ අධික බලපත්‍ර ගාස්තු ඉහළ දැමීම.
පිළියම: විකුණුම්කරුගේ ස්ථාවරත්වය ඇගයීම, Test assets වෙනත් මෙවලමකට මාරු කිරීමේ හැකියාව පරීක්ෂා කිරීම.

6. Open-Source Abandonment & Component Churn

අවදානම: Open-source ව්‍යාපෘතියක් නිර්මාපකයන් විසින් අත්හැර දැමීම හෝ එහි අභ්‍යන්තර packages නිතර වෙනස්වීම නිසා scripts බිඳවැටීම.
පිළියම: සක්‍රීය, පුළුල් ප්‍රජා සහයෝගයක් (Community) සහ LTS සහායක් ඇති මෙවලම් තෝරාගැනීම.

7. Incompatibility With Development Platform

අවදානම: පරීක්ෂණ මෙවලම ඉලක්කගත තාක්ෂණික පද්ධතිය, මෙහෙයුම් පද්ධතිය හෝ CI/CD පරිසරය සමඟ නොගැළපීම.
පිළියම: මෙවලම මිලදී ගැනීමට පෙර Proof-of-Concept (PoC) පරීක්ෂණයක් පැවැත්වීම.

8. Non-Compliance With Regulations & Safety Standards

අවදානම: වෛද්‍ය, ගුවන් හෝ මූල්‍ය වැනි දැඩි නීතිමය ප්‍රමිති (ISO 26262, FDA) සහිත ක්ෂේත්‍රවල නුසුදුසු මෙවලමක් තෝරාගැනීම.
පිළියම: අදාළ ක්ෂේත්‍ර නියාමන ප්‍රමිතීන්ට මෙවලම අනුකූලදැයි (Tool qualification) සහතික කරගැනීම.

විභාග විශේෂ අවධානය (Exam Flashpoint):
සමාගමක් සියලු පරීක්ෂණ ස්වයංක්‍රීය කළ නමුත්, සංවර්ධකයින් බොත්තම්වල ID වෙනස් කරන සෑම විටම Scripts යාවත්කාලීන කිරීමට සතියකට පැය 80 ක් වැයවී අසාර්ථක විය. මෙයින් නිරූපණය වන්නේ කුමන අවදානමද? → Risk #2: Inaccurate estimations of maintenance effort (නඩත්තු ශ්‍රමය වැරදියට තක්සේරු කිරීම)!

2. High-Yield Exam Flashpoints & Key Distinctions (විභාග විශේෂ කරුණු)

TOP 8 ISTQB CTFL v4.0.1 CHAPTER 6 EXAM TRAPS:
  1. "Test automation replaces human testers entirely" → අසත්‍යයකි! Automation මඟින් කරන්නේ කලින් අර්ථ දැක්වූ පරීක්ෂණ ධාවනය කිරීම පමණි. එයට මිනිස් විවේචනාත්මක චින්තනය හෝ exploratory පරීක්ෂාව ප්‍රතිස්ථාපනය කළ නොහැක.
  2. "A spreadsheet cannot be considered a test tool" → අසත්‍යයකි! විෂය නිර්දේශයට අනුව පරීක්ෂණ සඳහා උදවු වන ඕනෑම මෙවලමක් (පැතුරුම්පතක් වුවද) පරීක්ෂණ මෙවලමක් වේ!
  3. "Acquiring a powerful automation tool guarantees success" → අසත්‍යයකි! මෙවලමක් මිලදී ගත් පමණින් සාර්ථක විය නොහැක; හඳුන්වාදීම, පුහුණුව සහ නඩත්තුව අත්‍යවශ්‍ය වේ.
  4. "Test coverage measurement is easy to calculate manually" → අසත්‍යයකි! කේත ආවරණය (Statement/Branch coverage) අතින් ගණනය කළ නොහැකි තරම් සංකීර්ණ වන අතර ඒ සඳහා Coverage tools අනිවාර්ය වේ.
  5. "Automated regression suites have zero ongoing maintenance costs" → අසත්‍යයකි! මෘදුකාංගය වෙනස් වන සෑම විටම scripts යාවත්කාලීන කිරීමට සිදුවන බැවින් නඩත්තු වියදම ඉතා ඉහළය.
  6. "Open-source test tools carry no risks because they are free" → අසත්‍යයකි! Open-source මෙවලම් අත්හැර දැමීම (abandonment) සහ අභ්‍යන්තර updates බිඳවැටීම ප්‍රධාන අවදානම් වේ.
  7. "Test management tools are only used during test execution" → අසත්‍යයකි! ඒවා SDLC පුරාම (Requirements, Design, Execution, Defect tracking, Completion) භාවිත වේ.
  8. "Syllabus v4.0.1 requires candidates to know how to run a tool pilot project" → අසත්‍යයකි! v4.0.1 හිදී Pilot Project පිළිබඳ විස්තර විෂය නිර්දේශයෙන් ඉවත් කර ඇත.

Rapid Comparison: Manual vs. Automated Testing Sweet Spots

පරීක්ෂණ මානය (Dimension) Manual Testing වඩාත් සුදුසු අවස්ථා Automated Testing වඩාත් සුදුසු අවස්ථා
පරීක්ෂණයේ ස්වභාවය Exploratory, Usability, එක්වරක් පමණක් කරන ad-hoc පරීක්ෂණ. නැවත නැවත සිදුකරන පුනරාවර්තී Regression test suites.
මෘදුකාංගයේ ස්ථාවරත්වය වේගයෙන් වෙනස්වන prototypes සහ මුල් අදියරේ UI. ස්ථාවර, පරිණත interfaces සහ පුරෝකථනය කළ හැකි හැසිරීම්.
මානව සාධකය මිනිස් ඇස, UX හැඟීම, විවේචනාත්මක චින්තනය අවශ්‍ය වේ. වෙහෙසක් නැතිව එකම ආකාරයට නැවත නැවත ක්‍රියාත්මක වීම.
මිනුම් ලබාගැනීම පරිශීලක තෘප්තිය පිළිබඳ ආත්මීය (Subjective) ඇගයීම. වෛෂයික, සංකීර්ණ මිනුම් (Statement coverage %, Latency ms).
ධාවන වේගය මිනිසාගේ කියවීමේ හා ක්ලික් කිරීමේ වේගයට සීමා වේ. ක්ෂණිකයි; CI/CD pipeline තුළ සමාන්තරව (Parallel) ධාවනය වේ.

පරීක්ෂණ මඟින් ආවරණය කරන ලද කේත ව්‍යුහයන්ගේ (Statements, Branches) ප්‍රතිශතය වෛෂයිකව මනින මෙවලම.
Test Design Tool
අවශ්‍යතා, මාදිලි හෝ කේත විස්තර මත පදනම්ව Test cases උත්පාදනය කිරීමට සහාය වන මෙවලම.
Test Data Generation Tool
පරීක්ෂණ සඳහා අවශ්‍ය යථාර්ථවාදී හෝ කෘත්‍රිම (Synthetic/Sanitized) දත්ත ජනනය කිරීමට පහසුකම් සලසන මෙවලම.
Performance Testing Tool
විශාල පරිශීලක ප්‍රමාණයක් සහ ගනුදෙනු අනුකරණය කරමින් ප්‍රතිචාර කාලය සහ සම්පත් භාවිතය මනින මෙවලම.
DevOps Pipeline Tools (CI/CD)
ස්වයංක්‍රීය Build, Code integration සහ Deployment මෙහෙයවමින් නියමිත Quality gates වලදී පරීක්ෂණ ධාවනය කරවන මෙවලම්.
Review Support Tool
ලියකියවිලි බෙදාහැරීම, අදහස් එක්රැස් කිරීම, සහ දෝෂ සටහන් කිරීම හරහා සමාලෝචන ක්‍රියාවලියට සහාය වන මෙවලම.

4. Realistic ISTQB Practice Exam Questions & Detailed Rationales (Part 1)

Question 1 [K2 - FL-6.1.1]: Which of the following test tools is primarily designed to evaluate code without executing it, checking for coding standard violations and calculating cyclomatic complexity?
(පහත සඳහන් මෙවලම් අතුරින් කේතය ක්‍රියාත්මක නොකර, කේත සම්මතයන් උල්ලංඝනය වීම් පරීක්ෂා කිරීමට සහ Cyclomatic Complexity ගණනය කිරීමට ප්‍රධාන වශයෙන් නිර්මාණය කර ඇත්තේ කුමක්ද?)
A) Test execution tool
B) Dynamic performance testing tool
C) Static analysis tool
D) Test data preparation tool
Correct Answer: C
Rationale (සිංහල + English):
Static analysis tools මඟින් කේතය ධාවනය නොකර (without runtime execution) කේතයේ වැරදි, සම්මත උල්ලංඝනයන් සහ Cyclomatic complexity වැනි ව්‍යුහාත්මක මිනුම් ගණනය කරයි. Test execution tools (A) සහ Performance tools (B) ධාවනය වන කේතය dynamic ලෙස පරීක්ෂා කරයි.
Question 2 [K1 - FL-6.2.1]: Which of the following is an official POTENTIAL BENEFIT of test automation according to the ISTQB CTFL v4.0.1 syllabus?
(ISTQB CTFL v4.0.1 විෂය නිර්දේශයට අනුව පරීක්ෂණ ස්වයංක්‍රීයකරණයේ නිල විභව ප්‍රතිලාභයක් (Potential benefit) වන්නේ පහත සඳහන් කුමක්ද?)
A) Completely eliminating the requirement for human exploratory testing
B) Prevention of simple human errors through greater consistency and repeatability
C) Ensuring that test scripts never require maintenance once implemented
D) Guaranteeing 100% defect-free software releases
Correct Answer: B
Rationale (සිංහල + English):
විෂය නිර්දේශයේ 6.2 වගන්තිය අනුව "Prevention of simple human errors through greater consistency and repeatability" (වැඩි අනුකූලතාව සහ පුනරාවර්තනය හරහා සරල මානව දෝෂ වැළැක්වීම) යනු නිල ප්‍රතිලාභයකි. Automation මඟින් exploratory testing අවශ්‍යතාව නැති නොකරයි (A), Scripts වලට අඛණ්ඩ නඩත්තුවක් අවශ්‍ය වේ (C), සහ පරීක්ෂාවෙන් සියලු දෝෂ නැති බව ඔප්පු කළ නොහැක (D).
Question 3 [K2 - FL-6.1.1]: A testing team uses a Microsoft Excel spreadsheet to record test case identifiers, execution steps, expected outcomes, and actual pass/fail results. How does ISTQB classify this spreadsheet?
(පරීක්ෂණ කණ්ඩායමක් Test case IDs, පියවර, අපේක්ෂිත ප්‍රතිඵල සහ සැබෑ Pass/Fail ප්‍රතිඵල සටහන් කිරීමට Microsoft Excel පැතුරුම්පතක් භාවිත කරයි. ISTQB අනුව මෙම පැතුරුම්පත වර්ගීකරණය කරන්නේ කෙසේද?)
A) It cannot be classified as a test tool because it is general office productivity software.
B) It is considered a test tool because any software that assists in testing qualifies as a test tool.
C) It is classified strictly as a static analysis tool.
D) It is an automated test execution harness.
Correct Answer: B
Rationale (සිංහල + English):
විෂය නිර්දේශයේ 6.1 වගන්තිය පැහැදිලිවම සඳහන් කරන්නේ: "Any other tool that assists in testing (e.g., a spreadsheet is a test tool in the context of testing)." පරීක්ෂණ කටයුත්තක් සඳහා සහාය වන ඕනෑම මෘදුකාංගයක් පරීක්ෂණ සන්දර්භය තුළදී පරීක්ෂණ මෙවලමක් (Test Tool) වේ.
Question 4 [K1 - FL-6.2.1]: A software organization decides to adopt an open-source test automation framework. Which of the following represents a specific POTENTIAL RISK associated with this decision?
(මෘදුකාංග ආයතනයක් Open-source පරීක්ෂණ ස්වයංක්‍රීයකරණ රාමුවක් භාවිත කිරීමට තීරණය කරයි. මෙම තීරණය හා බැඳුණු නිශ්චිත විභව අවදානමක් (Potential risk) නිරූපණය කරන්නේ පහත කුමක්ද?)
A) The open-source project may be abandoned by its maintainers, resulting in no further updates or bug fixes.
B) Open-source tools always cost more in initial licensing fees than commercial enterprise tools.
C) Open-source tools can only be executed by developers and never by testers.
D) Open-source software cannot be integrated into DevOps CI/CD delivery pipelines.
Correct Answer: A
Rationale (සිංහල + English):
විෂය නිර්දේශයේ 6.2 වගන්තිය Open-source සම්බන්ධ ප්‍රධාන අවදානමක් ලෙස දක්වන්නේ: "Using an open-source software which may be abandoned, meaning that no further updates are available..." (නිර්මාපකයන් විසින් ව්‍යාපෘතිය අත්හැර දැමීම නිසා ඉදිරියට updates හෝ bug fixes නොලැබී යාමයි). Open-source මෙවලම් සඳහා බලපත්‍ර ගාස්තු නොමැත (B අසත්‍යයි), සහ ඒවා CI/CD pipelines සමඟ ඉතා පහසුවෙන් බද්ධ කළ හැක (D අසත්‍යයි).

Question 5 [K1 - FL-6.2.1]: Management at a tech startup expects that purchasing an advanced test automation tool will immediately reduce all testing effort to zero within the first month. Which test automation risk does this scenario demonstrate?
(නව තාක්ෂණික සමාගමක කළමනාකාරිත්වය අපේක්ෂා කරන්නේ උසස් ස්වයංක්‍රීයකරණ මෙවලමක් මිලදී ගැනීමෙන් පළමු මාසය තුළම සියලු පරීක්ෂණ පරිශ්‍රමය බිංදුව දක්වා අඩුකරගත හැකි බවයි. මෙම තත්ත්වයෙන් පෙන්නුම් කරන්නේ කුමන අවදානමද?)
A) The automation tool is not compatible with the development platform.
B) Choosing an unsuitable tool that fails to comply with safety regulations.
C) Unrealistic expectations about the benefits of a tool and inaccurate estimations of effort.
D) The tool vendor going out of business or being acquired by a competitor.
Correct Answer: C
Rationale (සිංහල + English):
මෙවලමක් ගත් සැණින් සියලු පරීක්ෂණ ශ්‍රමය නැතිවේ යැයි සිතීම යනු Unrealistic expectations (අතිශයෝක්ති අපේක්ෂාවන්) සහ මෙවලම ස්ථාපනය, පුහුණුව හා නඩත්තුව සඳහා වැයවන ශ්‍රමය නිසි ලෙස තක්සේරු නොකිරීම (Inaccurate estimations of effort) පිළිබඳ සම්භාව්‍ය උදාහරණයකි (Section 6.2).
Question 6 [K2 - FL-6.1.1]: Which tool category is essential when an organization needs to simulate 50,000 concurrent user requests hitting a payment gateway to measure response latency and server CPU saturation?
(ගෙවීම් පද්ධතියකට එකවර පරිශීලකයින් 50,000 කගේ ඉල්ලීම් ලැබෙන විට ප්‍රතිචාර කාලය සහ Server CPU භාවිතය මැනීමට ආයතනයකට අත්‍යවශ්‍ය වන මෙවලම් කාණ්ඩය කුමක්ද?)
A) Static code linters
B) Collaboration messaging tools
C) Non-functional testing tools (performance/load)
D) Review management tools
Correct Answer: C
Rationale (සිංහල + English):
පරිශීලකයින් 50,000 ක් එකවර පද්ධතියට සම්බන්ධ වීම අතින් (Manually) කළ නොහැකි කාර්යයකි. කාර්ය සාධනය (Performance), බර දරාගැනීම (Load), සහ CPU භාවිතය මැනීමට Non-functional testing tools අනිවාර්යයෙන්ම අවශ්‍ය වේ.
Question 7 [K1 - FL-6.2.1]: Which of the following is a benefit of test automation regarding test management and reporting?
(පරීක්ෂණ කළමනාකරණය සහ වාර්තාකරණය සම්බන්ධයෙන් පරීක්ෂණ ස්වයංක්‍රීයකරණයේ නිල ප්‍රතිලාභයක් වන්නේ පහත කුමක්ද?)
